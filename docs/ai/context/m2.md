## 关键设计决策与坑（真实工程实测）

1. **locator 必须含文件名**：数据库文件（Items/Weapons/Actors…）的 JSON root 都是数组，`$[1].name` 在不同文件指向不同文本。不带文件名 → stable ID 碰撞，upsert 互相覆盖（真实工程 2061 条实测发现）。格式定为 `{文件basename}::{JSON Pointer}`，如 `Map001.json::$.events[1].pages[0].list[3].parameters[0]`。
2. **401 参数可内嵌 `\n`**：MV 消息一条 401 内部就能含换行。`source.split("\n")` 无法还原"每条 401 该拿几行译文"。context_json 增加 `segments`（每区间的原文），write_back 按段分配译文行。
3. **extract 落库语义分离**：新增 `repo.upsert_extracted`——重提取只刷新源侧字段（source/locators/context/warnings），**不覆盖 translation/status**（同 ID 说明原文没变，译文仍有效）。游戏更新后重提取不抹掉已翻内容。
4. **write_back 必须字节读写**：`Path.read_text` 走 universal newline 会把 CRLF 翻译成 LF，破坏格式免疫。全部用 `read_bytes().decode("utf-8")` / `write_bytes(...encode)`。
5. **逐文件替换按 start 降序**：先改高偏移区间，低偏移区间不受长度变化影响。
6. **状态机补 `extracted → writing_back`**：人工在校对器翻完（不经 AI 流水线）直接回写是 M2 合法路径，原状态机没有这条边。
7. **插件入口必须相对导入**：伪包加载（`sys.modules[pkg_name].__path__=[插件目录]`）下 `import extract` 是绝对导入找不到兄弟模块，必须 `from .extract import ...`。
