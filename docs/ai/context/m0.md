## 主要 tradeoff 与实现决策

1. **uv workspace 根是虚拟项目**：要让根 `uv sync` 安装 core，根项目必须声明 `gt-core = { workspace = true }` 依赖，否则 `import gt_core` 失败（实测踩坑）。
2. **协议生成物位置**：路线图 1.2 的目录树（`protocol/generated/`）与生成命令（`gt_core/rpc/models.py`、`apps/desktop/src/rpc/models.ts`）矛盾。**按生成命令落地**到消费方，`protocol/generated/` 只放说明。
3. **枚举命名**：datamodel-codegen 在 jsonschema 模式无法给整型枚举语义名（`integer_1`…），也不支持 `enumNames`。方案：`generate.mjs` 做确定性后处理重命名 `PENDING/MACHINE/EDITED/CONFIRMED`（可复现、CI 校验），同时删掉 definitions 容器产生的无用 `Model` 根类。
4. **TS 命名**：json2ts 用 definition 的 `title` 命名类型，中文 title 会变成 `NoName` → title 改 ASCII（与 key 一致），中文放 description。
5. **PyInstaller onefile vs onedir**：Tauri externalBin 只要单文件 → M0 用 onefile（启动慢 ~1-2s，bootloader 双进程）；M5 计划改 onedir（启动快、core<40MB）。onefile 副作用：进程表出现父/子两个 `gt-core` 进程，杀进程测试按映像名杀即可。
6. **sidecar 崩溃检测**：shell 插件 `CommandEvent` 默认按行触发 `Stdout`（NDJSON 友好），`Terminated` 事件触发自动重启；ping 兜底补 spawn。**已验证杀进程自动恢复。**
7. **RPC 日志**：请求/响应逐行落 `logs/rpc-*.ndjson`（M1 排障生命线），stdout 保持纯净。

## 环境坑（Windows 实测）

- **uv 首次安装**：`pip install uv` 落在受保护 WindowsApps 目录不在 PATH；用官方安装器装到 `~/.local/bin`，再复制到 `~/bin` 让当前 bash 会话可用
- **代理**：pypi.org/npm/github 需代理；astral 安装器同样走代理才通
- **Python 协议帧**：必须 `stdin/stdout.reconfigure(encoding="utf-8", newline="\n")`，否则 cp936 中文乱码 + CRLF 破坏 NDJSON 帧（已处理）
- **gbk 控制台**：脚本 print 中 `✓/✗` 会 UnicodeEncodeError，用 ASCII OK/FAIL
- **pnpm10 拦截 esbuild 构建脚本**：根 `package.json` 加 `pnpm.onlyBuiltDependencies: ["esbuild"]` 放行，否则 vite build 失败
- **tauri 命令路径**：`tauri` CLI 在 desktop 包，根目录要用 `pnpm --filter desktop tauri dev`（直接 `pnpm tauri` 报 command not found）
- **TaskStop 杀 GUI 进程**：杀 pnpm 包装进程不会杀 detached 的 desktop.exe + sidecar，需手动 taskkill 清理
